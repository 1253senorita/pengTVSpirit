DI(Dependency Injection) 라이브러리 의존성 추가: DI는 모듈 간 결합도를 낮추고 테스트를 용이하게 만들어 주는 중요한 요소입니다. core 모듈은 다른 모든 모듈이 의존하기 때문에, core 모듈에 DI 라이브러리를 추가하는 것이 좋습니다.
Hilt: Dagger 기반의 DI 라이브러리입니다.
Koin: Kotlin DSL 기반의 DI 라이브러리입니다.
추가 의존성 예시 (build.gradle.kts - core 모듈):

dependencies {
            // Hilt
            implementation("com.google.dagger:hilt-android:2.50")
            ksp("com.google.dagger:hilt-compiler:2.50")

            // Koin (선택)
            // implementation("io.insert-koin:koin-android:3.5.3")
        }

DI를 위한 인터페이스 정의: core 모듈에는 각 모듈에서 필요한 의존성을 제공하는 인터페이스들을 정의해 두는 것이 좋습니다. 예를 들어, AuthRepository, DataRepository와 같은 인터페이스를 정의하고, 각 모듈에서 이를 구현합니다.
예시(core모듈내 인터페이스 )

// AuthRepository.kt
        interface AuthRepository {
            suspend fun register(user: User): Result<Unit>
            suspend fun login(user: User): Result<Unit>
            // ... 기타 인증 관련 메서드
        }

        // DataRepository.kt
        interface DataRepository {
            suspend fun getData(): Result<List<Data>>
            // ... 기타 데이터 관련 메서드
        }

Result Class: 작업 결과를 효과적으로 관리하기 위해 Result 클래스를 정의하여 반환값으로 사용하는것이 좋습니다.
예시(core모듈내 Result.kt)

// Result.kt
        sealed class Result<out R> {
            data class Success<out T>(val data: T) : Result<T>()
            data class Error(val exception: Exception) : Result<Nothing>()
        }


Network 유틸리티 : API를 호출하거나, 서버와 통신하기 위한 Network 모듈을 생성하여, 해당 코드를 core모듈에서 관리하는것이 좋습니다.
추가 설명 : Retrofit과 OkHttp를 사용해 network 모듈을 생성하면, API를 호출하는 코드, 서버와 통신하는 코드, 응답 데이터를 파싱하는 코드등을 관리 할수 있습니다.
데이터 유틸리티 : 저장소와 연동하여 데이터를 저장하고 불러오는 유틸리티를 생성합니다.
추가 설명 : DataStore 또는 SharedPreferences를 사용해, 사용자 정보를 저장하거나, 로그인 토큰을 저장하는 등 어플리케이션 내에 저장해야 할 데이터를 관리 합니다.
상태 관리 유틸리티 : 어플리케이션의 상태를 관리하는 유틸리티를 생성합니다.
추가 설명 : 어플리케이션의 상태는 loading, success, error 로 나누어, 사용자에게 현재상태를 보여줄수있도록 할수 있습니다. 또한 사용자 로그인을 포함한 어플리케이션의 현재 상태를 보여줄수 있도록 합니다.
모든 모듈에서 공통으로 사용하는 유틸리티 : 각 모듈에서 공통적으로 사용할수 있는 유틸리티를 추가합니다.
추가 설명 : 날짜와 시간을 계산하는 유틸리티, 리스트를 필터링하는 유틸리티, 해시 함수로 암호화를 하는 유틸리티 등등 을 공통으로 사용할수있도록 합니다.
모든 모듈에서 공통으로 사용하는 데이터 모델 : 각 모듈에서 공통적으로 사용할수 있는 데이터 모델을 추가합니다.
추가 설명 : 사용자 정보를 담은 data class , 서버와 주고받는 정보들에 대한 data class등을 생성합니다. 2. auth 모듈 보완
DI를 통한 의존성 주입: core 모듈에서 정의한 AuthRepository 인터페이스를 auth 모듈에서 구현하고, DI를 통해 auth 모듈의 컴포넌트(ViewModel 등)에 주입합니다.
Firebase Authentication 초기화: auth 모듈에서 Firebase Authentication을 초기화합니다.
인증 상태 관리: Flow 또는 StateFlow를 사용하여 인증 상태를 관리합니다.

예시 (ViewModel - auth 모듈):

class AuthViewModel(private val authRepository: AuthRepository) : ViewModel() {
            // 인증 상태를 StateFlow로 관리
            val authState = MutableStateFlow<AuthState>(AuthState.Loading)

            fun login(user: User) {
                viewModelScope.launch {
                    authState.value = AuthState.Loading
                    val result = authRepository.login(user)
                    authState.value = when (result) {
                        is Result.Success -> AuthState.LoggedIn
                        is Result.Error -> AuthState.LoggedOut
                    }
                }
            }
            // ... 기타 인증 관련 메서드
        }


인증 관련 API 호출: core모듈에 생성한 Network 모듈을 사용하여 인증관련 API를 호출할수 있습니다.
core 모듈 의존성 추가 : core 모듈에 선언한 데이터 모델, 유틸리티, 인터페이스를 사용하려면 auth 모듈에서 core 모듈 의존성을 추가해야 합니다. 3. data 모듈 보완
DI를 통한 의존성 주입: core 모듈에서 정의한 DataRepository 인터페이스를 data 모듈에서 구현하고, DI를 통해 data 모듈의 컴포넌트에 주입합니다.
Firebase Database 초기화: data 모듈에서 Firebase Realtime Database 또는 Firestore를 초기화합니다.
데이터 모델 정의: Firebase 데이터 구조에 맞는 데이터 모델을 data 모듈에 정의합니다.
데이터 관련 API 호출 : core모듈에 생성한 Network 모듈을 사용하여 데이터관련 API를 호출할수 있습니다.
core 모듈 의존성 추가 : core 모듈에 선언한 데이터 모델, 유틸리티, 인터페이스를 사용하려면 data 모듈에서 core 모듈 의존성을 추가해야 합니다. 4. ui 모듈 보완
ViewModel 의존성: auth 모듈과 data 모듈에서 구현한 AuthViewModel, DataViewModel 등을 ui 모듈에서 DI를 통해 주입받아 사용합니다.
추가 설명 : 각 모듈에 존재하는 Viewmodel 들을 DI를 통해 연결하고 사용하면, ViewModel 들에 결합도를 낮출수 있고 테스트에 용이 합니다.
화면별 Composable: 각 기능에 맞는 Composable 화면들을 ui 모듈에 구현합니다. (MainScreen, LoginScreen, DataListScreen 등)
Navigation: Navigation 그래프는 ui 모듈에서 정의합니다.
공통 UI 컴포넌트: core 모듈에서 정의한 공통 UI 컴포넌트를 사용하여 UI를 일관성 있게 구성합니다.
core,auth,data 모듈 의존성 추가: core,auth,data 모듈에서 생성한 Composable 함수, 데이터 모델, 인터페이스등을 사용하려면 ui 모듈에서 core,auth,data 모듈 의존성을 추가해야 합니다.
화면 이동 로직 : 화면 이동 로직을 구성하여 NavHost 에서 모든 화면을 관리해야 합니다. 5. app 모듈 보완
DI 설정: app 모듈에서 DI 설정을 합니다. Hilt를 사용하는 경우 @HiltAndroidApp 어노테이션을 적용합니다.
모듈 통합: 모든 모듈을 의존성으로 추가합니다.
NavHost: ui 모듈에서 정의한 NavHost 를 사용하여 모든 화면을 연결합니다.
Application: Application 클래스를 생성하여 Application 에서 필요한 설정을 합니다.
추가 설명 : Application 에서는 hilt 초기화, Firebase 초기화, DataStore 초기화등 어플리케이션이 시작할때 필요한 설정을 합니다.
ui,core,data,auth 모듈 의존성 추가 : 생성한 모듈들을 전부 사용하기위해 의존성을 추가합니다. **전체 모듈 의존성
