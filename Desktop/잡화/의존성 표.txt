### 주요 복습 사항
1. **버전 관리**: 의존성 버전을 중앙화하여 업데이트 시 유지보수 편의성을 극대화.
2. **Library 참조**: 그룹과 모듈 기반으로 라이브러리 구조를 정의하여 명확성 유지.
3. **Plugin 설정**: 프로젝트 빌드 환경을 설정하며 Android/Kotlin 관련 플러그인 통합.
4. **특수 상황 처리**: 로컬 파일 참조, 동적 버전, 환경 변수 기반 의존성 추가로 유연성 제공.
5. **멀티 모듈 관리**: 공통 유틸리티를 독립적으로 구성하여 코드 재사용성과 확장성 확보.

### 주요 내용 정리

1. **중앙 집중 관리 (`libs.versions.toml`)**:
   - 의존성 버전을 중앙에서 관리하여 유지보수가 용이.
   - `versions` 섹션에서 업데이트 후 모든 참조에 자동 반영.

2. **모듈화 관리**:
   - 멀티 모듈 구조를 통해 의존성을 독립적으로 관리하며, 필요한 모듈만 패치 가능.
   - 특정 모듈에서 발생한 문제를 분리하여 해결.

3. **예외적 관리 방식**:
   - `.jar` 또는 `.aar` 파일은 직접 파일 교체 방식으로 패치 가능.
   - 핫픽스 버전은 개별 모듈에 적용 후, 문제가 해결되면 중앙 버전 관리로 되돌림.

4. **패치 및 업데이트 프로세스**:
   - 패치 적용 후, Gradle Sync를 실행하여 참조가 올바르게 연결되었는지 검증.
   - 테스트 환경에서 새로운 패치가 애플리케이션에 영향을 미치지 않는지 확인.

### 주요 추가 방식 설명

1. **Git 기반 의존성 관리**:
   - 특정 GitHub 리포지토리에서 코드베이스를 직접 참조하여 실시간으로 최신 상태를 유지.
   - 예: `implementation("com.github.User:Repo:1.0.0")`.

2. **로컬 및 JitPack 의존성**:
   - 로컬 경로에서 제공하는 `.pom` 또는 `.jar` 파일, 혹은 JitPack을 통한 외부 종속성을 관리하여 유연성 확보.

3. **환경 변수 조건부 추가**:
   - 환경 변수 플래그를 사용해 특정 의존성을 조건부로 추가하여 빌드 시점에 유연하게 라이브러리를 변경 가능.

4. **운영 환경과 개발 환경 분리**:
   - 디버깅 및 테스트 라이브러리는 개발 환경에만 포함하고 운영 환경에서는 배포되지 않도록 구성.

5. **멀티플랫폼 종속성 관리**:
   - Kotlin Multiplatform 프로젝트에서 공통 코드와 플랫폼별 코드를 독립적으로 관리 가능.

6. **동적 및 실험적 버전 관리**:
   - 동적 버전(`+`)을 참조하여 항상 최신 상태 유지, 실험적 버전으로 새로운 기능 테스트.

이 구조는 여러 환경과 요구사항에 따른 의존성 관리 및 추가 방식을 다루며, 프로젝트의 확장성과 유연성을 높입니다. 추가로 필요한 방식이나 특별한 상황이 있다면 알려주세요! 😊

### 프로젝트 단 역할 추가 설명
#### 1. **루트 프로젝트 정의**
루트 프로젝트에서는 전체 프로젝트 구조와 주요 의존성 관리가 이루어집니다.
- 저장소 정의: 모든 의존성을 검색할 저장소(`google()`, `mavenCentral()`)를 설정.
- Version Catalog: 주요 라이브러리 버전과 이름을 중앙에서 관리.

#### 2. **앱 모듈 정의**
앱 모듈에서는 실제 애플리케이션과 관련된 라이브러리를 참조합니다.
- UI 구성 라이브러리: Jetpack Compose와 관련된 모든 UI 라이브러리를 참조.
- 기능별 라이브러리: Firebase, 네트워킹, 데이터베이스와 같은 기능 구현에 필요한 라이브러리를 참조.

#### 3. **멀티 모듈 정의**
멀티 모듈 프로젝트에서는 `settings.gradle.kts`에서 모듈을 포함하고, 각 모듈별로 의존성을 관리합니다.
- 루트 프로젝트에서 공통 모듈이나 라이브러리를 정의하여 여러 모듈에서 재사용.

### 사용 예시

#### `settings.gradle.kts`
```kotlin
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
    }
    versionCatalogs {
        create("libs") {
            library("androidx-core", "androidx.core", "core-ktx").version("1.9.0")
            library("compose-ui", "androidx.compose.ui", "ui").version("1.4.3")
        }
    }
}
include(":app")
include(":sharedModule")
```

#### `libs.versions.toml`
```toml
[versions]
androidx-core = "1.9.0"
```
